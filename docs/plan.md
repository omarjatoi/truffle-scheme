milestone. Later milestones list just their exit criteria until they start.

`Checks` and `Tests` checks are green (AGENTS.md). Agents may change
`docs/design.md` too, in a PR of its own that says why (AGENTS.md).

## M0 · Suite bootstrap and spike

Set up the mx suite, then answer the two questions the design depends on
before anything else is built on top of them.

- [x] **M0-01 · mx suite bootstrap**
  - `mx.r7rs/suite.py`:
    - `mxversion`.
    - The Truffle 25.5.5.0.3 jars from Maven Central as mx libraries with
      digests (design.md D11): `truffle-api`, `truffle-runtime`,
      `truffle-compiler`, `truffle-dsl-processor`, `polyglot`, and their SDK
      dependencies.
    - The projects listed in AGENTS.md "Layout", as empty stubs, with
      `TRUFFLE_DSL_PROCESSOR` only where generated code will be needed
      (`scheme.runtime`, `scheme.builtins`).
    - A JUnit test project, `tests/scheme/test`.
  - `mx.r7rs/mx_r7rs.py`: every command in AGENTS.md "Commands", registered
    and wired to gate tasks. Commands whose machinery doesn't exist yet print
    a clear "not implemented until <task>" and exit nonzero. `torture` and
    `--compile` are flags the runtime reads, which do nothing until M2.
    `--compile` turns on immediate, synchronous compilation and makes
    compilation failures errors.
  - A check, run on every mx invocation, that the GraalVM version on
    `JAVA_HOME` equals the Truffle library version, failing with a clear
    message otherwise.
  - `.github/workflows/gate.yml`: on every PR, enter the Nix dev shell (which
    provides GraalVM) and run the full `mx gate`.
  - **Done when:**
    - `mx build` builds a stub `TruffleLanguage` that evaluates an integer
      literal.
    - `mx unittest` runs one JUnit test against it.
    - The same test passes with the Graal JIT in compile-immediately mode,
      and a test asserts that the optimizing Truffle runtime is active, not
      the fallback runtime.
    - The gate workflow runs on the PR and passes.
    - Every command in AGENTS.md either works or reports that it isn't
      implemented yet. **If any command in AGENTS.md is wrong for mx, fix
      AGENTS.md in the same PR.**
- [x] **M0-02 · Spike: frame copy and multi-shot resume** *(needs M0-01)*
  - Write a minimal Bytecode DSL interpreter in a throwaway project,
    `scheme.spike`, excluded from the gate and deleted at M0-04. Give it a call
    operation, a custom `@Yield SuspendFrame`, and a `Capture` marker, as in
    design.md "Continuations".
  - Capture across at least 3 frames, then resume the same continuation
    **twice**, copying each frame before resuming with Truffle's copy
    (`BytecodeNode.createCopiedFrame` / `BytecodeFrame.copy()`).
  - Keep `enableBlockScoping` at its default (on), and include a capture
    from inside a nested scope.
  - **Done when** tests show:
    - The two resumes are independent: locals and the operand stack of one
      don't leak into the other.
    - A variable in a `Box` (design.md D2) is **shared** across both resumes.
    - It works both with compilation disabled and with `--compile`.
  - **Report:** whether Truffle's frame copy is enough to resume a
    `ContinuationRootNode` more than once, which APIs were used, how block
    scoping behaved, and any gaps or workarounds.
- [x] **M0-03 · Spike: cost of the call-site check under the JIT** *(needs M0-02)*
  - Compare `fib(30)` and `tak` with and without the call → `IsCapture` →
    `SuspendFrame` protocol, on the GraalVM 25.5 JIT.
  - **Done when** the report has overhead numbers and evidence (graphs dumped
    with `-Djdk.graal.Dump`, or compilation traces) of whether the capture
    branch is folded away at call sites that never see a capture.
- [x] **M0-04 · Decision** *(human; done by an agent at the maintainer's request)*
  - Fill in the "Spike-dependent" box in design.md with the results.
  - Record go/no-go in the Decisions section.
  - Delete `scheme.spike`.

**Exit:** M0-04 done.

## M1 · Core

Tasks marked *(spike-independent)* can start as soon as M0-01 lands, while
the spike is still running.

- [x] **M1-01 · Conformance harness** *(spike-independent)*
  - Vendor chibi's `r7rs-tests.scm` into `tests/r7rs/`, split into one file
    per section.
  - Add a `(chibi test)` shim (`test`, `test-begin`, `test-end`,
    `test-error`, ...) that reports results to the runner.
  - `mx r7rs-test [section]` runs each section in one JVM.
  - `mx r7rs-status` regenerates the status block in this file, and a gate
    task fails if that block is stale.
  - **Done when** every section runs (all failing is expected) and the status
    block is generated.
- [x] **M1-02 · Differential runner** *(spike-independent)*
  - `mx r7rs-diff file.scm` runs the file under chibi and under our
    implementation, then compares stdout and exit status (design.md D8).
- [x] **M1-03 · Value types and printer** *(spike-independent)*
  - All D1 value types, with arithmetic stubbed to fixnums and flonums only.
  - `write`, `display`, `write-shared` and `write-simple`, with cycle
    handling (D9).
- [x] **M1-04 · Reader** *(spike-independent; needs M1-03)*
  - The full R7RS datum syntax: every number syntax (parsed into the D1
    types, or rejected clearly while the tower is stubbed), datum labels,
    block comments, `#;` datum comments, and `#!fold-case` /
    `#!no-fold-case`.
  - No Java recursion proportional to nesting depth (rule 4).
- [x] **M1-05 · Core compiler, call protocol and trampoline** *(needs M0-04 go)*
  - Core forms (D3) → Bytecode DSL, with closure conversion and assignment
    conversion (D2).
  - `CallSiteEmitter` and the `TailCall` trampoline. Self tail calls become
    loops.
  - Global cells with `Assumption`s (D7).
- [x] **M1-06 · Vertical slice** *(needs M1-02, M1-04, M1-05)*
  - A hand-written program using only core forms defines `fib`, prints
    `(fib 25)`, and matches chibi under `mx r7rs-diff`.
  - A 10M-iteration tail-recursive loop runs in constant space.

**Exit:** all M1 tasks done, `mx checks` and `mx tests` green, the harness reports
a status for every section, and the vertical slice matches chibi.

## M2 · Continuations

Tasks follow design.md "Continuations" and "Dynamic environment", D4, D5 and D6,
and the M0 spike results recorded there. M2-07 runs the `tests/spec/` cases
that M2-00 writes.

- [x] **M2-00 · Spec tests**
  - Write `tests/spec/`: `tail-*` (tail calls in constant space under a memory
    limit), `cont-*` (capture, escape, re-entry, multi-shot) and `deep-*` (deep
    non-tail recursion; deep data through the reader, printer and `equal?`).
  - Define the case format `mx r7rs-spec` runs: for example a program, its
    expected stdout and exit status, and the JVM limits to run it under.
- [x] **M2-01 · Prelude bootstrap and DynEnv**
  - Load `src/prelude/*.scm` into every context at initialization, written in
    core forms only until the expander (M3), on top of `%`-primitives (D5).
  - `DynEnv { winders, parameterization, handlers }` as one immutable record in
    a per-context slot, with `%`-primitives to read and replace it
    (design.md "Dynamic environment").
  - **Done when** a prelude procedure is callable from a program, and unit tests
    cover DynEnv. The primitives used are leaves (rule 1).
- [x] **M2-02 · call/cc: capture and re-entry** *(needs M2-01)*
  - `call/cc` returns a `Capture` (D5). Each call site's `SuspendFrame` adds
    its segment. The program's root prompt (D6) completes the capture into a
    continuation object that also holds the current `DynEnv`.
  - Invoking a continuation resumes its segments innermost first, each from a
    copied frame (design.md "Copying a frame"), through a `DirectCallNode`
    inline cache keyed on the `ContinuationRootNode`. A capture during a resume
    adds the segments not yet resumed. Never resume an original frame.
  - **Done when** tests show:
    - escapes, re-entry and multi-shot work (a generator; R7RS's examples);
    - re-entering a continuation captured in one top-level form carries on
      through the following forms (D6);
    - the same results interpreted and with `--compile`;
    - `tests/diff/` programs using `call/cc` match chibi.
- [x] **M2-03 · Prompts** *(needs M2-02)*
  - The internal `%prompt` with tags: a capture stops at the nearest prompt
    whose tag matches (D4). Each REPL input and each `eval` gets its own
    prompt (D6). Not exposed to Scheme programs (D4).
  - **Done when** unit tests cover nested prompts with different tags, and a
    capture across a prompt boundary.
- [x] **M2-04 · dynamic-wind and rewind** *(needs M2-02)*
  - `dynamic-wind` in the prelude (D5). One `rewind(from, to)` for every change
    of control (continuation invocation, escape, prompt return, `exit`). It
    runs after- and before-thunks along the path through the common ancestor,
    each in its own dynamic environment.
  - **Done when** R7RS §6.10's `dynamic-wind` example (`connect` … `talk2`)
    gives R7RS's result; re-entry runs the before-thunks again; and
    `tests/diff/` programs using `dynamic-wind` match chibi.
- [x] **M2-05 · Stack-depth spill** *(needs M2-02)*
  - A depth counter forces a capture past a threshold, then execution resumes
    on a fresh Java stack (design.md "Continuations").
  - **Done when** the M1-06 control, as a 1,000,000-deep non-tail recursion,
    returns the right answer under `-Xss256k -Xmx512m` (a new `mx tests space`
    case), interpreted and with the JIT. The depth is 1M rather than 10M because
    spilling moves frames to the heap, about 350 bytes each, so 10M pending
    frames would need about 3.5 GB of heap. The Java stack stays constant
    either way.
- [x] **M2-06 · Torture mode** *(needs M2-02)*
  - `--torture` (`-Dscheme.torture=true`): capture and resume at every
    non-tail call, resuming every segment twice (AGENTS.md rules 2 and 3).
    `mx r7rs-test --torture`, `mx tests torture`, and a CI step.
  - **Done when** everything that passes without torture passes with it: unit
    tests, `tests/diff/`, and every conformance case that passes normally.
- [x] **M2-07 · Spec runner** *(needs M2-00)*
  - `mx r7rs-spec` runs `tests/spec/` in the format M2-00 defines, under each
    case's limits. Also as `mx tests spec` and a CI step.
  - **Done when** every case runs and reports pass or fail. M2's exit needs
    all of them to pass.

**Exit:**
- `call/cc` capture and re-entry, prompts (D4), `dynamic-wind` with
  `rewind` (design.md "Dynamic environment"), and stack-depth spill all work.
- All of `tests/spec/` passes, except the cases that need a later task
  (`tests/spec/README.md`), which are reported as skipped and name that task.
- `mx r7rs-test --torture` is green on every test that passes without it.

## M3 · Expander and prelude

Tasks marked *(early)* need nothing from M2 that is still open (M2-00 and M2-07
only add the spec tests and their runner), so they can start before M2's exit.
They follow design.md D3, D4, D5 and D7.

- [x] **M3-01 · Syntax objects and source positions** *(early)*
  - The reader can produce syntax objects: a datum, its set of scopes, and
    its source position (`SourceSection`), with no Java recursion (rule 4).
    `read` still produces plain data.
  - Errors from the compiler name the source line.
  - **Done when** unit tests cover syntax-object construction and stripping
    (`syntax->datum`), and a syntax error in a program reports its line.
- [x] **M3-02 · Expander core** *(early; needs M3-01)*
  - The sets-of-scopes expander (Flatt 2016) in Java, replacing the
    `Analyzer`. It expands the core forms (D3) into the existing core AST:
    `quote`, `lambda`, `if`, `set!`, `define`, `begin`, `letrec*`,
    `define-syntax`, `let-syntax`, `letrec-syntax`, and the internal
    `%prompt`/`%guard`.
  - It handles internal definition contexts, and definitions that macros
    expand into. No Java recursion proportional to nesting depth (rule 4).
  - **Done when** every existing test passes on the new expander, and unit
    tests cover scope resolution: shadowing, keywords shadowed by local
    variables, and definition contexts.
- [x] **M3-03 · syntax-rules** *(early; needs M3-02)*
  - Hygienic `syntax-rules` with literals, `_`, ellipsis at any depth, tail
    patterns after an ellipsis, vector and dotted patterns, and a custom
    ellipsis identifier (R7RS §4.3.2).
  - **Done when** unit tests cover R7RS §4.3's examples, including the
    hygiene ones (`my-or` with a `temp` binding, `if` shadowed at the use
    site), and chibi section 4.3's `syntax-rules` cases pass when run
    through the test shim directly.
- [x] **M3-04 · Libraries** *(early; needs M3-02)*
  - `define-library` with `export` (and `rename`), `import` sets (`only`,
    `except`, `prefix`, `rename`), `include`, `include-ci`, `include-library-declarations`
    and `cond-expand` (feature identifiers and `(library ...)`).
  - Each library is instantiated once per context on first import, its
    globals are cells, and assigning to an imported binding is an error (D7).
  - The primitives become the internal library `(r7rs %primitives)`, and
    the prelude moves into standard library `.sld` files under
    `src/prelude/` (D7).
  - User libraries are found on a search path (`-I dir`, read through
    `TruffleFile`, D10). Programs (R7RS §5.1) are an import set plus a body.
    The conformance runner passes `tests/lib` so `(chibi test)` resolves.
  - **Done when** unit tests cover library instantiation, the import set
    forms, renamed exports, `cond-expand`, and `include`, and every vendored
    section *starts* (imports resolve), so the status block shows real
    numbers.
- [x] **M3-05 · Derived syntax** *(needs M3-03, M3-04)*
  - R7RS §7.3's `syntax-rules` definitions in the prelude: `let`, `let*`,
    `letrec`, named `let`, `let-values`, `let*-values`, `define-values`,
    `cond` (with `=>`), `case` (with `=>`), `and`, `or`, `when`, `unless`,
    `do`, `case-lambda`, and `delay`, `delay-force` and `make-promise` (the
    space-safe reference implementation, D9).
  - `quasiquote` (with nesting and vectors) in the expander.
  - Named `let` and `do` must still compile their self tail calls to loops.
  - **Done when** R7RS §4.2's examples pass as unit tests, and
    `tests/diff/` programs using the derived forms match chibi.
- [x] **M3-06 · guard, parameterize and records** *(needs M3-05)*
  - `raise`, `raise-continuable`, `with-exception-handler` and `error` in
    the prelude through `DynEnv.handlers` (D8). Primitive errors are raised
    in the frame that called the primitive (D8).
  - `guard` as `%guard` (D4): capture to the guard's prompt, rewind, evaluate
    the clauses in the guard's continuation, and if none matches, reinstate
    the segment and `raise-continuable` in the original dynamic environment.
  - `make-parameter` and `parameterize` through
    `DynEnv.parameterization`, with converters.
  - `define-record-type` on `SRecord`/`SRecordType` (D1).
  - **Done when** R7RS §4.2.7 (guard) and §4.2.6 (parameterize) examples,
    §6.11's exception examples, and record tests pass, and the same holds
    under `--torture`.
- [x] **M3-07 · Fan-out layout** *(needs M3-04)*
  - One builtins file, one prelude file and one registration point per M4
    area (numeric tower, characters and strings, lists and vectors,
    bytevectors, control and exceptions, I/O and ports, `eval` and
    environments, process context and time), so parallel M4 agents don't
    edit the same files.
  - **Done when** each area's files exist with a stub, AGENTS.md says which
    files belong to which area, and adding a primitive to one area touches
    only that area's files.
- [x] **M3-08 · Sections 4.x and 5** *(needs M3-05, M3-06, M3-07)*
  - Whatever chibi sections 4.1, 4.2, 4.3 and 5 still need, from the areas'
    files.
  - **Done when** those four sections pass in full, normally and under
    `--torture`, and the status block shows it.

- [x] **M3-09 · Source locations** *(needs M3-04)*
  - The core AST carries each form's `SourceSection` (from its syntax object,
    M3-01) to the code generator, which wraps operations in Bytecode DSL
    source sections; `storeBytecodeIndexInFrame` keeps locations exact across
    yields (design.md D13).
  - Syntax errors name the file as well as the line and column, including in
    libraries and included files.
  - **Done when** a runtime error's guest stack trace names `file:line:col`
    for each Scheme frame (a unit test reads `getPolyglotStackTrace()`), an
    error inside a library names that library's file, and the M0-03 call-site
    numbers are unchanged within noise (`fib(30)`, `tak`).
- [x] **M3-10 · Errors and tools through Truffle** *(needs M3-09)*
  - `SchemeError` reports its exception type through interop: syntax errors
    are `PARSE_ERROR` (with incomplete-source detection for unfinished
    input), `exit` is `EXIT`, everything else `RUNTIME_ERROR`, and each has
    its source location (design.md D13).
  - Tag instrumentation (`enableTagInstrumentation`): root, root-body,
    statement, call and expression tags on the generated bytecode, declared
    in `@ProvidedTags`.
  - **Done when** unit tests show `isSyntaxError()` and `isIncompleteSource()`
    on syntax errors, a Truffle instrument sees statement and call events with
    Scheme source locations, and the same tests pass under `--torture`.

**Exit:**
- The sets-of-scopes expander (D3), `define-library`, `import`, `include`
  and `cond-expand` work.
- The R7RS §7.3 derived syntax is in the prelude, along with `guard` (D4),
  `parameterize` and `define-record-type`.
- Each fan-out area has its own builtins, prelude and registration files, so
  M4 agents don't collide.
- Chibi sections 4.x and 5.x pass.
- Errors and guest stack traces name the file, line and column, syntax
  errors are parse errors to embedders, and Truffle's tools (debugger,
  Chrome inspector) see Scheme statements and calls (D13).

## M4 · Fan-out (parallel agents)

builtins file, its prelude and declarations files, its own tests
(`tests/scheme/test/<Area>Test.java`, `tests/diff/<area>-*.scm`). If an area
needs a procedure another area owns, add it to that area's files in a separate
PR first. Every task is *(early)*: they need only M3, so they can run in
parallel. Section counts are from the status block when M4 was drafted.

- [x] **M4-01 · Numeric tower** *(early)*

  - **Done when** section 6.2 (129/211) passes in full, normally and under

- [x] **M4-02 · Characters, strings and symbols** *(early)*
  - R7RS §6.5–6.7 and `(scheme char)`: every character procedure (simple case

  - **Done when** sections 6.5 (6/17), 6.6 (0/79) and 6.7 (10/130) pass in

- [x] **M4-03 · Lists and vectors** *(early)*

    an optional predicate, the `vector` procedures (`vector-copy`

    `vector-map` and `vector-for-each` in the prelude (D5), and the rest of

  - **Done when** sections 6.4 (39/65) and 6.8 (10/43) pass in full,

- [x] **M4-04 · Bytevectors** *(early)*
  - R7RS §6.9 on `SBytevector`: `bytevector` `make-bytevector`

    `bytevector-copy` `bytevector-copy!` `bytevector-append`, `utf8->string`

  - **Done when** section 6.9 (0/39) passes in full, normally and under

- [x] **M4-05 · Control, booleans and exceptions** *(early)*
  - R7RS §6.3, §6.10 and §6.11: `boolean=?`, `procedure?`, the rest of
    `apply` `map` `for-each` `call-with-values` `dynamic-wind` (multiple

- [x] **M4-06 · Input and output** *(early)*
  - R7RS §6.13 and `(scheme read)`, `(scheme write)`, `(scheme file)`:

## M5 · Performance

Starts once M4's exit holds (both conformance suites pass in full), so every
benchmark measures a conforming implementation. Benchmark first, then optimize
against the numbers: every optimization task reports before and after on the
M5-01 benchmarks and M5-02's report.

- [ ] **M5-01 · Benchmark suites under `mx benchmark`** *(early)*
  - Vendor, read-only like `tests/r7rs/` (with provenance, license and a
    re-vendor command), ecraven's `r7rs-benchmarks`
    (https://ecraven.github.io/r7rs-benchmarks/) and Larceny's
    `test/Benchmarking/R7RS`.
  - Run each program under `mx benchmark` (D11) with the JIT, measuring time
    after warmup (several in-process iterations, as the suites' drivers
    allow) and peak memory, and checking each program's own result. Also an
    interpreter-only run.
  - **Done when** every program of both sets runs and passes its own check
    under `mx benchmark`, with results in `mx benchmark`'s JSON format; a
    program we can't run yet is a listed failure with its reason, fixed in a
    follow-up conformance PR.
- [ ] **M5-02 · Comparative report** *(needs M5-01)*
  - Add the other R7RS implementations nixpkgs has (Chez Scheme, Gauche,
    Chicken, Guile, Racket's R7RS mode, as available) to the dev shell
    (`flake.nix`, which this task may change), next to chibi-scheme, and run
    the same programs on each with the suites' own conventions, so numbers are
    comparable with ecraven's published tables.
  - Generate a report (per benchmark: time relative to the fastest, failures;
    for us the interpreter/JIT split and peak memory) as a page in the repo
    (`docs/benchmarks.md`) and as a CI artifact, reproducible with one `mx`
    command.
  - **Done when** the report is generated by that command, committed, and
    attached to a CI run.
- [ ] **M5-03 · Context startup** *(needs M5-01)*
  - Cache the compiled standard libraries with Bytecode DSL serialization
    (design.md D13's proposal), so a context deserializes the prelude instead
    of expanding and compiling it. Measure context creation, and
    `unittest-compile`'s wall time, before and after.
  - **Done when** context creation is measurably faster and every suite still
    passes in every mode.
- [ ] **M5-04 · Escape-only `call/cc`** *(needs M5-01)*
  - The fast path from design.md "Continuations": when the compiler proves a
    `call/cc`'s continuation is only called directly in its body, compile it to
    an escape (`unwindExceptions`) instead of a capture.
  - **Done when** the benchmarks that escape (e.g. `ctak`, `fibc`) improve,
    and `tests/spec/cont-*` and torture still pass.
- [ ] **M5-05 · Fixing Letrec and closure-free `let`** *(needs M5-01)*
  - Fixing Letrec (D2): no boxes for groups of mutually recursive lambdas.
    Compile `((lambda (x ...) body) arg ...)`, which `let`, `or` and named
    `let` expand to, without allocating a closure.
  - **Done when** the affected benchmarks improve and every suite passes in
    every mode.
- [ ] **M5-06 · Vector storage strategies** *(needs M5-01)*
  - Specialized storage for vectors (D10's deferral): e.g. `long[]`/`double[]`

    store, with DSL specializations on the accessors.
  - **Done when** the vector-heavy benchmarks improve and every suite passes.
- [x] **M5-07 · `equal?` fast path** *(early)*
  - D9's union-find algorithm with a fast path for small trees (Adams &
    Dybvig), replacing M3-08's coinductive walk; still iterative (rule 4).
  - **Done when** `tests/spec/deep-equal` and the `equal?` tests pass and the
    benchmarks that use `equal?` don't regress.
- [ ] **M5-08 · Thresholds in CI** *(needs M5-02 to M5-07)*

## M6 · Release

Make it usable on the platform it's built on (design.md D10, D13, D17).

- The `scheme` launcher on GraalVM's launcher framework (D17): programs,
  `-I`, `command-line`, a REPL with incomplete-input continuation, and the
  standard engine and tool options.
- Tools: a distribution with the Chrome inspector, DAP and the CPU sampler,
  and CI smoke tests that set a breakpoint, step, and sample a Scheme
  program. Spilled frames (heap segments, M2-05) appear in guest stack traces
  and in the debugger's stack.
- Interop for embedders (D10): Scheme values through `InteropLibrary`, with
  tests from Java and from another Truffle language if one is available.
- Documentation: a README with build and usage, the conformance status, and
  an embedding guide.
- *(optional)* A native-image launcher, if GraalVM CE's native-image is in
  the dev shell; otherwise a recorded decision to leave it for later.

**Exit:** the launcher and tools work end to end with smoke tests in CI,
embedders can call Scheme procedures with Scheme values crossing the
boundary, and the README documents all of it.
